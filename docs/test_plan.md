# Test Plan

## 1. Цель тестирования

Проверить, что игровая логика, события, действия, смена ходов,
условия победы и поражения, журнал и основные элементы интерфейса
работают в соответствии с правилами игры.

## 2. Объекты тестирования

- стартовое состояние игроков;
- игровые ресурсы;
- расчёт престижа;
- случайные события;
- действия игроков;
- выбор цели;
- ограничения действий;
- смена ходов;
- выбывание игроков;
- условия победы;
- условия поражения;
- ничья;
- журнал событий;
- пользовательский интерфейс;
- завершение и перезапуск игры.

## 3. Методы тестирования

### 3.1. Unit-тестирование

Проверка отдельных функций и компонентов игровой логики.

Используется для проверки:

- расчёта престижа;
- изменения ресурсов;
- проверки стоимости действий;
- условий победы и поражения;
- выбора случайного события;
- проверки допустимости действий и целей;
- смены текущего игрока.

### 3.2. Интеграционное тестирование

Проверка взаимодействия нескольких частей игровой логики.

Используется для проверки:

- взаимодействия событий и состояния игрока;
- взаимодействия действий и ресурсов;
- определения результата партии после события или действия;
- смены ходов;
- выбывания игрока и пропуска его в очереди.

### 3.3. Ручное функциональное тестирование

Проверка игры непосредственно через пользовательский интерфейс.

Используется для проверки:

- отображения игроков;
- отображения ресурсов и престижа;
- работы кнопок;
- отображения событий;
- выбора действия и цели;
- передачи хода;
- журнала;
- окончания партии.

### 3.4. Граничное тестирование

Проверка значений на границах условий.

Основные граничные значения:

- ресурс = 0;
- паника = 9;
- паника = 10;
- паника > 10;
- белки = 1;
- белки = 0;
- престиж = 29;
- престиж = 30;
- престиж > 30.

### 3.5. Регрессионное тестирование

Повторная проверка уже работающих функций после исправления ошибок.

Цель: Убедиться, что исправление одной ошибки не нарушило другие части игры.

## 4. Тестовые сценарии

### T1. Проверка стартового состояния

Метод: Unit-тестирование.

Шаги:

1. Запустить новую игру.
2. Проверить состояние каждого из четырёх кланов.
3. Проверить значения всех ресурсов.

Ожидаемый результат:

Каждый клан начинает игру со значениями:

- орехи = 10;
- шишкоины = 10;
- дупла = 5;
- белки = 10;
- паника = 0.

### T2. Проверка расчёта престижа

Метод: Unit-тестирование.

Формула: prestige = land * 2 + money // 5 + people // 5 - smuta

Шаги:

1. Создать игрока с известными значениями ресурсов.
2. Рассчитать престиж.
3. Сравнить результат с ожидаемым значением.

Ожидаемый результат: Престиж рассчитывается строго по указанной формуле.

Стартовый престиж:

5 * 2 + 10 // 5 + 10 // 5 - 0 = 14.

### T3. Проверка поражения при панике

Метод: Unit-тестирование и граничное тестирование.

Шаги:

1. Установить панику равной 9.
2. Проверить состояние игрока.
3. Установить панику равной 10.
4. Проверить состояние игрока.
5. Проверить значение паники больше 10.

Ожидаемый результат:

При панике < 10 игрок не выбывает.

При панике >= 10 игрок выбывает.

Паника может превышать 10.

### T4. Проверка поражения при отсутствии белок

Метод: Unit-тестирование и граничное тестирование.

Шаги:

1. Установить количество белок равным 1.
2. Проверить состояние игрока.
3. Установить количество белок равным 0.
4. Проверить состояние игрока.

Ожидаемый результат:

При количестве белок > 0 игрок продолжает игру.

При количестве белок <= 0 игрок выбывает.

### T5. Проверка нижней границы ресурсов

Метод: Unit-тестирование и граничное тестирование.

Шаги:

1. Создать ситуацию, при которой событие уменьшает ресурс.
2. Установить ресурс равным небольшому значению.
3. Применить событие.
4. Проверить итоговое значение ресурса.

Ожидаемый результат:

Ресурсы не становятся отрицательными.

Если потери превышают имеющийся запас, ресурс устанавливается в 0.

### T6. Проверка стоимости действий

Метод: Unit-тестирование.

Шаги:

1. Проверить действие при достаточном количестве ресурсов.
2. Проверить действие при недостаточном количестве ресурсов.
3. Проверить ситуацию, когда не хватает только одного необходимого ресурса.
4. Проверить, что частичная оплата не выполняется.

Ожидаемый результат:

При достаточном количестве ресурсов действие доступно.

При недостаточном количестве ресурсов действие недоступно.

Частичная оплата и долг запрещены.

### T7. Проверка случайного события

Метод: Unit-тестирование и интеграционное тестирование.

Шаги:

1. Начать ход текущего игрока.
2. Запустить событие.
3. Проверить, что выбрано одно семейство событий.
4. Проверить положительный или отрицательный исход.
5. Проверить изменение ресурсов текущего игрока.

Ожидаемый результат:

За обычный ход происходит ровно одно неуправляемое событие.

Событие применяется только к текущему игроку.

После применения события состояние игрока обновляется.

### T8. Проверка вероятности случайных событий

Метод: Статистическое тестирование.

Шаги:

1. Запустить большое количество генераций событий.
2. Подсчитать количество положительных исходов.
3. Подсчитать количество отрицательных исходов.
4. Сравнить полученные значения.

Ожидаемый результат:

Положительный и отрицательный исходы имеют вероятность 50/50.

При большом количестве испытаний их доли должны быть приблизительно равными.

Каждое из восьми семейств выбирается равновероятно.

### T9. Проверка действий игрока

Метод: Unit-тестирование и интеграционное тестирование.

Шаги:

1. Выбрать действие.
2. Выбрать другого действующего клана.
3. Проверить стоимость действия.
4. Подтвердить действие.
5. Проверить изменение ресурсов инициатора.
6. Проверить изменение ресурсов цели.

Ожидаемый результат:

Стоимость и эффект действия применяются один раз.

Изменения ресурсов соответствуют правилам выбранного действия.

Ответного хода цели нет.

### T10. Проверка выбора цели

Метод: Unit-тестирование и ручное функциональное тестирование.

Шаги:

1. Выбрать действие.
2. Открыть список целей.
3. Попробовать выбрать самого себя.
4. Попробовать выбрать действующего соперника.
5. При наличии выбывшего игрока попробовать выбрать его.

Ожидаемый результат:

Самого себя выбрать нельзя.

Допустимого действующего соперника выбрать можно.

Выбывшего игрока выбрать нельзя.

Недопустимые цели заблокированы с объяснением причины.

### T11. Проверка порядка ходов

Метод: Unit-тестирование и интеграционное тестирование.

Шаги:

1. Начать игру.
2. Проверить текущего игрока.
3. Завершить его ход.
4. Передать ход следующему игроку.
5. Повторить для всех игроков.

Ожидаемый результат:

Порядок ходов:

1 → 2 → 3 → 4 → 1

Выбывшие игроки пропускаются.

### T12. Проверка выбывания игрока

Метод: Интеграционное и ручное функциональное тестирование.

Шаги:

1. Создать условие поражения игрока.
2. Проверить его выбывание.
3. Проверить порядок ходов.
4. Проверить возможность взаимодействия с выбывшим игроком.

Ожидаемый результат:

Выбывший игрок:

- больше не получает события;
- больше не выполняет действия;
- не может быть целью;
- пропускается при смене хода.

### T13. Проверка победы по престижу

Метод: Unit-тестирование и граничное тестирование.

Шаги:

1. Проверить престиж 29.
2. Проверить престиж 30.
3. Проверить престиж больше 30.

Ожидаемый результат:

При prestige < 30 победа по престижу не наступает.

При prestige >= 30 действующий клан может победить.

### T14. Проверка победы последнего действующего клана

Метод: Интеграционное и ручное функциональное тестирование.

Шаги:

1. Вывести из игры всех игроков, кроме одного.
2. Проверить состояние последнего действующего клана.
3. Проверить результат партии.

Ожидаемый результат:

Если остаётся один действующий клан, он объявляется победителем.

Клан без белок не считается действующим.

### T15. Проверка ничьей

Метод: Интеграционное тестирование.

Шаги:

1. Создать ситуацию, при которой все кланы выбывают.
2. Проверить состояние игры.
3. Проверить итоговый экран.

Ожидаемый результат: Если действующих кланов не осталось, игра заканчивается ничьей.

### T16. Проверка приоритета поражения

Метод: Unit-тестирование и граничное тестирование.

Шаги:

1. Создать ситуацию, в которой после события или действия игрок одновременно достигает условия поражения и высокого престижа.
2. Проверить результат партии.

Ожидаемый результат:

Поражение проверяется раньше победы по престижу.

Игрок, выполнивший условие поражения, выбывает.

### T17. Проверка вынужденного пропуска действия

Метод: Интеграционное и ручное функциональное тестирование.

Шаги:

1. Создать ситуацию, в которой у текущего игрока нет ни одной допустимой пары «действие + цель».
2. Проверить интерфейс.
3. Нажать «Пропустить действие».
4. Проверить состояние игры.

Ожидаемый результат:

Появляется возможность «Пропустить действие».

Ресурсы игрока не изменяются.

Новое событие не запускается.

Ход передаётся следующему действующему клану.

### T18. Проверка одного события и одного действия за ход

Метод: Интеграционное тестирование.

Шаги:

1. Начать обычный ход.
2. Получить случайное событие.
3. Завершить обработку события.
4. Выполнить одно действие.
5. Проверить передачу хода.

Ожидаемый результат:

Обычный ход содержит:

- одно неуправляемое событие;
- одно управляемое действие.

Повторный клик или возврат из выбора цели не создаёт новое событие.

### T19. Проверка журнала событий

Метод: Ручное функциональное и интеграционное тестирование.

Шаги:

1. Выполнить событие.
2. Выполнить действие.
3. Проверить журнал.
4. Проверить количество отображаемых сообщений.
5. Проверить новую игру.

Ожидаемый результат:

В журнале отображаются:

- события;
- действия;
- вынужденные пропуски;
- выбывания;
- результат партии.

На экране отображаются последние пять сообщений.

После новой игры старые сообщения отсутствуют.

### T20. Проверка пользовательского интерфейса

Метод: Ручное функциональное тестирование.

Проверить:

- отображение четырёх кланов;
- отображение ресурсов;
- отображение престижа;
- выделение текущего игрока;
- отображение выбывшего игрока;
- кнопки «Начать ход»;
- кнопку «Подтвердить действие»;
- кнопку «Назад»;
- кнопку «Передать ход»;
- кнопку «Пропустить действие»;
- карточку случайного события;
- журнал;
- итог партии;
- кнопку «Новая игра».

Ожидаемый результат:

Элементы интерфейса отображаются и активируются только на подходящей стадии игры.

Недоступные действия и цели нельзя подтвердить.

## 5. Ручной чек-лист

### Запуск игры

- [ ] Игра запускается без ошибок.
- [ ] Отображаются четыре клана.
- [ ] Отображаются стартовые ресурсы.
- [ ] Отображается стартовый престиж.
- [ ] Правильно обозначен текущий игрок.

### События

- [ ] При начале хода появляется одно событие.
- [ ] Событие применяется к текущему игроку.
- [ ] Отображается карточка события.
- [ ] Повторный клик не создаёт второе событие.
- [ ] После завершения события можно перейти к действию.

### Действия

- [ ] Отображаются доступные действия.
- [ ] Недоступные действия заблокированы.
- [ ] Стоимость действия проверяется до подтверждения.
- [ ] Частичная оплата не выполняется.
- [ ] Самого себя выбрать нельзя.
- [ ] Выбывшего игрока выбрать нельзя.
- [ ] До подтверждения можно изменить действие или цель.
- [ ] После подтверждения действие применяется один раз.

### Ресурсы

- [ ] Ресурсы изменяются согласно правилам.
- [ ] Ресурсы не становятся отрицательными.
- [ ] Паника может превышать 10.
- [ ] Нулевой запас орехов сам по себе не приводит к поражению.

### Смена ходов

- [ ] Ходы идут в порядке 1 → 2 → 3 → 4 → 1.
- [ ] Выбывшие игроки пропускаются.
- [ ] После передачи хода событие следующего игрока не запускается автоматически.
- [ ] Событие запускается только после «Начать ход».
- [ ] При отсутствии допустимого действия работает «Пропустить действие».

### Выбывание

- [ ] Игрок выбывает при панике >= 10.
- [ ] Игрок выбывает при количестве белок <= 0.
- [ ] Выбывший игрок не получает новые события.
- [ ] Выбывший игрок не может выполнять действия.
- [ ] Выбывший игрок не может быть целью.

### Победа и поражение

- [ ] Победа при prestige >= 30 определяется корректно.
- [ ] Победа последнего действующего клана определяется корректно.
- [ ] При отсутствии действующих кланов определяется ничья.
- [ ] Поражение имеет приоритет над победой по престижу.
- [ ] После окончания партии действия заблокированы.
- [ ] Отображается причина окончания партии.

### Журнал

- [ ] События записываются в журнал.
- [ ] Действия записываются в журнал.
- [ ] Выбывания записываются в журнал.
- [ ] Вынужденные пропуски записываются в журнал.
- [ ] Результат партии записывается в журнал.
- [ ] На экране отображаются последние пять сообщений.
- [ ] После новой игры старый журнал очищается.

### Новая игра

- [ ] Кнопка «Новая игра» доступна после завершения партии.
- [ ] Ресурсы возвращаются к стартовым значениям.
- [ ] Первый игрок восстанавливается.
- [ ] Все четыре клана снова активны.
- [ ] Журнал очищается.

## 6. Критерии завершения тестирования

Тестирование считается завершённым, если:

- все основные тестовые сценарии выполнены;
- автоматические тесты проходят;
- ручной чек-лист пройден;
- критические ошибки отсутствуют;
- найденные ошибки исправлены или задокументированы;
- исправленные ошибки прошли повторное тестирование;
- регрессионная проверка пройдена;
- игровая логика соответствует утверждённым правилам игры.
